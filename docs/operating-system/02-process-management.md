## 1. 进程状态机转换规则

- **就绪态 → 运行态**：被进程调度程序选中，获得 CPU 时间片。
- **运行态 → 就绪态**：时间片耗尽或被更高优先级进程抢占。
- **运行态 → 阻塞态**：主动请求某一资源未满足（如等待 I/O 或执行 $P$ 操作）。
- **阻塞态 → 就绪态**：所等待的事件发生（如 I/O 完成或被 $V$ 操作唤醒）。

## 2. 典型 CPU 调度算法全景对比

| 调度算法 | 抢占性 | 优点 | 缺点 / 是否产生饥饿 |
|:---|:---:|:---|:---|
| **FCFS (先来先服务)** | 非抢占 | 算法简单、公平 | 长作业有利，短作业不利（护航效应） |
| **SJF / SPF (短作业优先)** | 均可 | **平均等待时间 / 周转时间最短** | **会导致长作业饥饿** |
| **HRRN (高响应比优先)** | 非抢占 | 兼顾长短作业，无饥饿 | 响应比 $R = \frac{\text{等待时间} + \text{服务时间}}{\text{服务时间}} \ge 1$ |
| **RR (时间片轮转)** | 抢占 | 响应时间极佳 | 时间片过大退化为 FCFS，过小切换开销剧增 |
| **多级反馈队列** | 抢占 | 408 综合最优，兼顾长短与交互 | 各队列时间片递增，自动降级 |

## 3. 死锁产生 4 大必要条件与银行家算法

::: info 💡 死锁 4 大必要条件

$$
\text{① 互斥使用} \quad \text{② 不可剥夺} \quad \text{③ 请求并保持} \quad \text{④ 循环等待}
$$

:::

- **银行家算法**：在分配资源前，先预判分配后系统是否处于**安全状态**（能否找到至少一个合法安全序列）。若安全才正式分配。
