## 🧭 体系结构与分层模型

### ❓ TCP/IP 包含几层？与 OSI 7 层如何对应？

* **应用层 (Application Layer)**：类似于 OSI 的会话层、表示层、应用层。
* **传输层 (Transport Layer)**：对应 OSI 的传输层。
* **网际层 (Internet Layer)**：对应 OSI 的网络层。
* **网络接口层 (Network Interface Layer)**：对应 OSI 的数据链路层 + 物理层。

---

### ❓ OSI 7 层模型中，每层核心功能是什么？

| 层次 | 名称 | 核心功能速记 |
| :---: | :--- | :--- |
| **7** | **应用层** | 传输报文解决通信问题，直接为用户提供应用接口与服务。 |
| **6** | **表示层** | 数据格式转换、数据压缩与解压缩、数据加密与解密。 |
| **5** | **会话层** | ① 建立、管理、终止进程间的会话；② 从校验点（同步点）处恢复通信。 |
| **4** | **传输层** | ① 提供端到端（进程间）可靠/不可靠的数据传输；② 差错控制；③ 流量控制。 |
| **3** | **网络层** | ① 分组与路由选择；② 差错控制；③ 流量控制；④ 拥塞控制。 |
| **2** | **数据链路层** | ① 组帧（成帧）；② 差错控制（检错）；③ 流量控制；④ 访问控制（控制信道）。 |
| **1** | **物理层** | 在物理媒体上实现原始**比特流的透明传输**。 |

### ❓ PDU 和 SDU 有什么区别与联系？

::: tip 💡 核心巧记口诀
* **PDU** = **P**rotocol Data Unit（**协议**数据单元，带上了本层协议控制信息）
* **SDU** = **S**ervice Data Unit（**服务**数据单元，上一层传来的原始有效载荷）
:::

* **核心封装公式**：
  $$\text{SDU} + \text{PCI} = \text{PDU}$$
  * **解释**：收到上一层发来的 PDU 作为本层的 SDU，再加上本层的 PCI（Protocol Control Information，协议控制信息/报头），组装构成本层的 PDU，随后交给低一层传输。
* **各层 PDU 专有名词（考研选择题高频）**：
  * **物理层**：比特流 (Bit)
  * **数据链路层**：帧 (Frame)
  * **网络层**：分组 / 数据报 (Packet / Datagram)
  * **传输层**：报文段 (Segment，TCP) 或 用户数据报 (UDP)

## ⚡ 交换方式与连接可靠性对比

### ❓ 面向连接 / 无连接的协议与概念辨析

| 层次 | 协议 / 技术概念 | 面向连接 / 无连接 | 可靠性保证机制 |
| :--- | :--- | :---: | :--- |
| **物理层** | **电路交换** | 面向连接 | 无差错控制（直接占用物理信道） |
| **物理层** | **报文交换** | 面向非连接 | 可靠性由通信子网保证 |
| **网络层** | **分组交换（数据报）** | 面向非连接 | 可靠性由**端系统主机**保证 |
| **网络层** | **分组交换（虚电路）** | 面向连接 | 可靠性由**通信子网**保证 |
| **链路层** | **以太网 (802.3)** | 面向非连接 | 不可靠，可靠性由上层（传输层/应用层）保证 |
| **链路层** | **CSMA 系列** | 面向非连接 | 可靠性由上层保证 |
| **链路层** | **PPP 协议** | 面向连接 | 不可靠，只检错（CRC）、无纠错、无确认重传 |
| **传输层** | **TCP** | 面向连接 | 可靠传输（由端到端确认应答、重传机制保证） |
| **传输层** | **UDP** | 面向非连接 | 不可靠，可靠性由应用层自行保证 |
| **应用层** | **HTTP** | 面向非连接（无状态） | 依托于下层 TCP 的可靠连接 |

## 📊 考研 16 大核心协议层级归属与依赖全景表

### ❓ 核心协议依赖关系与端口号速查

| 协议名称 | 中文全称 | 所在层次 | 下层依赖协议与端口号 | 核心考研功能 |
| :--- | :--- | :---: | :---: | :--- |
| **POP3** | 邮局协议第3版 | 应用层 | **TCP (110)** | 接收邮件（将邮件从服务器拉取到本地） |
| **SMTP** | 简单邮件传输协议 | 应用层 | **TCP (25)** | 发送邮件（客户端向服务器发、或服务器间转发） |
| **DNS** | 域名系统 | 应用层 | **UDP (53)** | 域名解析为 IP（亦可 IP 反查域名） |
| **TFTP** | 简单文件传输协议 | 应用层 | **UDP (69)** | 小文件简单传输（UDP小巧开销小） |
| **SNMP** | 简单网络管理协议 | 应用层 | **UDP (161/162)** | 网络设备监控与集中管理 |
| **NFS** | 网络文件系统 | 应用层 | **TCP / UDP** | 跨主机共享与挂载网络文件 |
| **TELNET** | 远程终端协议 | 应用层 | **TCP (23)** | 明文远程登录终端 |
| **HTTP** | 超文本传输协议 | 应用层 | **TCP (80)** | Web 网页资源超文本传输 |
| **FTP** | 文件传输协议 | 应用层 | **TCP (20 数据, 21 控制)** | 跨主机可靠文件传输（双连接架构） |
| **PPP** | 点对点协议 | 数据链路层 | 物理层 | 广域网点对点链路成帧与差错检测 |
| **RIP** | 路由信息协议 | 应用层 | **UDP (520)** | 内部网关协议，基于**距离-向量算法**（跳数 $\le 15$） |
| **OSPF** | 开放最短路径优先 | 网络层 | **IP (协议号 89)** | 内部网关协议，基于**链路状态算法**（Dijkstra） |
| **BGP** | 边界网关协议 | 应用层 | **TCP (179)** | 外部网关协议，基于**路径-向量算法** |
| **ARP** | 地址解析协议 | 网络层/链路层 | 数据链路层 | 将 IP 地址解析映射为对应物理 MAC 地址 |
| **DHCP** | 动态主机配置协议 | 应用层 | **UDP (67 服务端, 68 客户端)** | 局域网主机即插即用动态获取 IP 地址及网关 |
| **ICMP** | 网际控制报文协议 | 网络层 | **IP (协议号 1)** | 报告 IP 数据报交付中的差错与异常（Ping / Traceroute） |

::: tip 💡 408 经典命题避坑陷阱
* **RIP 为什么是应用层协议？** 因为 RIP 报文直接封装在 **UDP 数据报** 中传输！
* **OSPF 为什么是网络层协议？** 因为 OSPF 报文直接封装在 **IP 数据报** 中传输（不走传输层）！
* **BGP 为什么是应用层协议？** 因为 BGP 路由器之间需要建立稳定的 **TCP 连接**（端口 179）传递路由向量！
:::
