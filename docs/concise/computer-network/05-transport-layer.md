## 1. TCP vs UDP 核心特性对比表

| 特性维度 | TCP (传输控制协议) | UDP (用户数据报协议) |
|:---|:---|:---|
| **连接性** | 面向连接（三次握手建立连接，四次挥手断开） | 无连接（发送前无需握手） |
| **可靠性** | **可靠交付**（无差错、不丢失、不重复、按序到达） | **尽最大努力交付**（不保证可靠性） |
| **通信方式** | 严格点对点单播（一对一） | 支持单播、多播 (组播)、广播（一对多、多对多） |
| **传输模式** | **面向字节流**（将数据视为无结构的字节序列流） | **面向报文**（保留应用层报文边界，不合并也不拆分） |
| **首部开销** | 较大：最小 **20 字节**，最大 60 字节 | 极小：固定 **8 字节**（源端口/目的端口/长度/校验和 各 2B） |
| **流量与拥塞** | 提供流量控制（滑动窗口）与拥塞控制（4 大机制） | 无流量控制，无拥塞控制（适合实时音视频/DNS/DHCP） |

## 2. TCP 报文段首部 6 大控制标志位速查

| 控制位 | 标志全称 | 核心功能与置 1 时的语义 |
|:---|:---|:---|
| **URG** | Urgent | 紧急指针有效，指示该报文中有高优先级紧急数据，插队优先发送 |
| **ACK** | Acknowledgment | **确认号有效**。连接建立后的所有正常交互报文段 ACK 均必须置 1 |
| **PSH** | Push | 接收方应尽快将此报文交付给上层应用，不再等待接收缓存填满 |
| **RST** | Reset | TCP 连接复位，表示连接出现严重错误，需强制释放并重新建立连接 |
| **SYN** | Synchronize | **同步序号**，用于连接建立。`SYN=1, ACK=0` (请求) 或 `SYN=1, ACK=1` (同意) |
| **FIN** | Finish | **释放连接**，指示发送方数据已全部发送完毕，要求释放该方向的连接 |

## 3. TCP 拥塞控制 4 大机制演化规律

::: info 💡 拥塞控制 4 大机制大一统规律
1. **慢开始 (Slow Start)**：$cwnd$ 从 1 MSS 开始，每经过一个 RTT，$cwnd$ **指数翻倍** ($1 \rightarrow 2 \rightarrow 4 \rightarrow 8 \dots$)，直到达到慢开始门限 $ssthresh$；
2. **拥塞避免 (Congestion Avoidance)**：当 $cwnd \ge ssthresh$ 时，改为**加法增大**，每经过一个 RTT，$cwnd$ **线性自增 1 MSS**；
3. **网络超时 (Timeout - 发生严重拥塞)**：
   - 慢开始门限降为发生拥塞时窗口的一半：$ssthresh_{\text{new}} = \max(2, \; \lfloor cwnd_{\text{current}} / 2 \rfloor)$；
   - 拥塞窗口立即跌回起点：$cwnd = 1 \text{ MSS}$，重新执行慢开始。
4. **收到 3 个冗余 ACK (快重传与快恢复 - 发生个别丢包)**：
   - 发送方立即重传丢失段（**快重传**）；
   - $ssthresh_{\text{new}} = \max(2, \; \lfloor cwnd / 2 \rfloor)$；
   - 拥塞窗口直接置为新门限：$cwnd = ssthresh_{\text{new}}$（**快恢复**），随后直接进入**拥塞避免线性递增**。
:::

## 4. TCP 流量控制与滑动窗口计算

::: tip 💡 实际发送窗口决定准则
$$W = \min(cwnd, \; rwnd)$$
- **2010 题 39 真题精解**：甲发送 $MSS=1000\text{B}$，当前 $cwnd=4000\text{B}$。甲向乙连续发 2 个段（0~999 与 1000~1999），收到乙对第 1 个段的确认（通告 $rwnd=2000\text{B}$）。
- 此时有效发送窗口 $W = \min(4000, 2000) = 2000\text{B}$（覆盖 1000~2999 字节）。扣除第 2 个段（1000~1999 字节）已发未确认占用的 1000B，**甲还可向乙发送 1000 字节**。
- **持续计时器**：用于解决接收方发送 $rwnd>0$ 窗口更新报文丢失导致的死锁。超时后发送方主动发送 1 字节**零窗口探测报文**。
:::

## 5. TCP 三次握手与四次挥手

```
【三次握手 (连接建立)】
客户端 (SYN_SENT)   ---- SYN=1, seq=x ---------------> 服务端 (LISTEN -> SYN_RCVD)
客户端 (ESTABLISHED) <--- SYN=1, ACK=1, seq=y, ack=x+1 - 服务端
客户端               ---- ACK=1, seq=x+1, ack=y+1 ----> 服务端 (ESTABLISHED)

【四次挥手 (连接释放)】
客户端 (FIN_WAIT_1)  ---- FIN=1, seq=u ---------------> 服务端 (CLOSE_WAIT)
客户端 (FIN_WAIT_2)  <--- ACK=1, seq=v, ack=u+1 -------- 服务端
客户端 (TIME_WAIT)   <--- FIN=1, ACK=1, seq=w, ack=u+1 - 服务端 (LAST_ACK)
客户端 (等待 2MSL)   ---- ACK=1, seq=u+1, ack=w+1 ----> 服务端 (CLOSED)
```
- **TIME_WAIT 等待 $2\text{MSL}$ 原因**：保证客户端发送的最后一个 ACK 报文能够到达服务端；使本连接内产生的所有报文段均在网络中消逝。

## 6. 408 核心真题精析

### 📝 【2024 年 题 38】TCP 建连、慢开始传输与断开综合时延计算
- 📺 **精讲视频**：[计算机网络408考研2024年真题解析（第38题）_哔哩哔哩_bilibili](https://www.bilibili.com/video/BV1VE411A7Ak/?t=3665.3&p=16&vd_source=82d10a6ac42fc540b554068775f4bb8d)
- **题干**：发送 $3000\text{ B}$ 数据，$\text{RTT}=10\text{ ms}$，$\text{MSL}=30\text{ s}$，$\text{MSS}=1000\text{ B}$，忽略发送时延。从 H 请求建连到进入 CLOSED 为止至少需要多少时间？
- **分步推导四步法**：
  1. **建连 + 捎带第 1 段 (1 RTT)**：第 3 次握手捎带 $1\text{ MSS}$ 数据 ($1000\text{ B}$)；
  2. **慢开始发剩余 2 段 (1 RTT)**：收到确认后 $cwnd$ 翻倍为 $2\text{ MSS}$，一次发完剩余 $2000\text{ B}$；
  3. **四报文释放 (2 RTT)**：H 发 FIN ➔ S 回 FIN+ACK ➔ H 回 ACK（进入 TIME-WAIT）；
  4. **TIME-WAIT 等待 (2 MSL)**：$2\text{MSL} = 2 \times 30\text{ s} = 60\text{ s}$；
  5. **总耗时**：$\text{Total} = 4\text{ RTT} + 2\text{MSL} = 4 \times 10\text{ ms} + 60\text{ s} = \mathbf{60.04\text{ s}}$（**选 D**）。
### 📝 【2024 年 题 39】UDP 校验和二进制反码求和计算
- 📺 **精讲视频**：[计算机网络408考研2024年真题解析（第39题）_哔哩哔哩_bilibili](https://www.bilibili.com/video/BV1VE411A7Ak/?t=4394.7&p=16&vd_source=82d10a6ac42fc540b554068775f4bb8d)
- **题干**：中间和 `1011 1001 1011 0110` 加上 `0110 0101 1100 0101`，最终得到的校验和是？
- **三步秒杀推导**：
  1. **普通加法**：`1011 1001 1011 0110` + `0110 0101 1100 0101` = `(1) 0001 1111 0111 1011`（第 17 位产生进位 1）；
  2. **循环进位 (+1)**：`0001 1111 0111 1011` + `1` = `0001 1111 0111 1100`（此为累加和，选项 B 陷阱）；
  3. **按位取反码**：`~ 0001 1111 0111 1100` = `1110 0000 1000 0011`（**正确答案：C**）。
