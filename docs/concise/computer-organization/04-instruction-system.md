## 🔢 扩展操作码技术与容量计算

### ❓ 扩展操作码核心设计原则

* **前缀编码特性**：短操作码绝对不能成为长操作码的前缀（类似哈夫曼树，保证译码无二义性）。
* **二地址 $\to$ 一地址 $\to$ 零地址递推**：高层指令保留至少一个状态码作为扩展标志，供下一层低地址指令继续扩展。

---

### ❓ 408 经典大题算例：定长操作码 vs 变长操作码

> **设系统参数**：指令字长为 **16 位**，每个操作数地址码占 **6 位**。

#### 题型 1：定长操作码设计
* 若采用定长操作码，留给操作码的固定位数为：
  $$16 - 6 - 6 = \mathbf{4\text{ 位}}$$
* 操作码总状态数为 $2^4 = 16$ 种。
* 若已定义零地址指令 $P$ 条、一地址指令 $Q$ 条，则二地址指令最多还能支持：
  $$\mathbf{16 - P - Q \quad \text{条}}$$

#### 题型 2：变长操作码（前缀扩展码）设计
* 设二地址指令占用了 $X$ 种编码（$X < 16$），则剩余可用扩展前缀为：
  $$M = 16 - X$$
* 每个可用前缀借用第一个 6 位地址码扩展，可派生出 $2^6 = 64$ 种一地址指令；
* 设留出 $K$ 个一地址前缀用于进一步扩展零地址指令，每个前缀可借用第二个 6 位地址码产生 64 种零地址指令；
* 若已知最终定义了 $Y$ 条零地址指令，则需占用的前缀数为：
  $$K \times 64 = Y \implies K = \frac{Y}{64}$$
* 因此，系统最终最多可容纳的一地址指令数量为：
  $$\mathbf{(16 - X) \times 64 - \frac{Y}{64} \quad \text{条}}$$

## 🎯 9 大寻址方式与有效地址 (EA) 计算

```
指令格式: [ 操作码 OP | 寻址特征 M | 形式地址 A ]
```

| 寻址方式 | 有效地址 (EA) 计算公式 | 访存取数次数 | 核心应用场景与考研特征 |
| :--- | :--- | :---: | :--- |
| **立即寻址** | 操作数直接存放在形式地址 $A$ 中 | **0 次** | 用于初始化常量（如 `MOV AX, #100`），执行速度最快 |
| **直接寻址** | $$EA = A$$ | **1 次** | 形式地址直接指明操作数的主存绝对物理地址 |
| **隐含寻址** | 操作数地址隐含在特定寄存器（如 ACC） | **0 次** | 简化指令字长（如累加器单操作数加法） |
| **间接寻址** | $$EA = (A)$$（一次间址） | **2 次** | 扩大寻址范围，便于子程序编制与指针操作 |
| **寄存器寻址** | 操作数在寄存器 $R_i$ 中，无需访存 | **0 次** | 指令字长短，执行极快（如 `ADD R1, R2`） |
| **寄存器间接寻址** | $$EA = (R_i)$$ | **1 次** | 寄存器存放主存地址，兼顾指令长度与指针灵活性 |
| **基址寻址** | $$EA = (BR) + A$$ | **1 次** | **面向操作系统**，便于多道程序动态浮动与内存再定位 |
| **变址寻址** | $$EA = (IX) + A$$ | **1 次** | **面向用户程序员**，形式地址 $A$ 固定，$IX$ 自动自增，便于遍历数组与向量 |
| **相对寻址** | $$EA = (PC) + A$$ | **1 次** | **面向程序相对跳转**，便于编写与浮动重定位的与位置无关代码 (PIC) |

::: tip 💡 核心三址辨析口诀
* **基址**：基址寄存器（BR/通用）+ 偏移 $A$ $\to$ **OS 分配基址，程序员改偏移**，用于程序重定位！
* **变址**：变址寄存器（IX）+ 偏移 $A$ $\to$ **程序员改变址，基准偏移 $A$ 不动**，用于循环数组！
* **相对**：$PC$ + 偏移 $A$ $\to$ **用于转移指令跳转**！
:::

## ⚖️ CISC 与 RISC 架构深度横评

| 对比维度 | CISC (复杂指令集计算机，如 x86) | RISC (精简指令集计算机，如 ARM, RISC-V) |
| :--- | :--- | :--- |
| **指令系统规模** | 指令种类庞大（数百条），变长指令字 | 仅保留精简常用指令（数十到百余条），**定长指令字** |
| **访存限制** | 绝大多数指令均可直接访问主存操作数 | **仅 LOAD / STORE 指令允许访存**，其余全部在寄存器间进行 |
| **指令执行周期** | 大多数指令需要多个时钟周期完成 | **绝大多数指令在 1 个时钟周期内完成** |
| **通用寄存器数量** | 数量较少（通常 8~16 个） | **数量极其丰富（通常 32 个以上）**，大量数据驻留寄存器 |
| **控制器实现方式** | 绝大多数采用 **微程序控制器** | 普遍采用 **硬布线逻辑控制器**（硬连线速度极快） |
| **流水线支持** | 流水线阶段难对齐，控制复杂度极高 | **天然极佳支持指令流水线**，各阶段执行时间高度均衡 |
