## 2. 典型 CPU 调度算法全景对比

| 调度算法 | 是否可抢占 | 核心调度准则 / 公式 | 优点 | 缺点 / 饥饿现象 |
|:---|:---:|:---|:---|:---|
| **先来先服务 (FCFS)** | 非抢占 | 按作业/进程到达就绪队列先后排序 | 算法极其简单公平 | 对长作业有利，对短作业极不利（护航效应） |
| **短作业优先 (SJF)** | 均可 | 优先调度估计运行时间最短的作业 | **平均等待时间最短** | 长作业产生**饥饿 (Starvation)** 现象 |
| **高响应比优先 (HRRN)** | 非抢占 | 响应比 $R_p = \frac{\text{等待时间 } W + \text{服务时间 } S}{\text{服务时间 } S} = 1 + \frac{W}{S}$ | 兼顾短作业与长作业，不会饥饿 | 每次调度需计算响应比，开销较大 |
| **时间片轮转 (RR)** | 抢占式 | 按 FCFS 排队，每个进程仅运行一个时间片 $q$ | 响应及时，适合分时系统 | 时间片过小上下文切换开销大，过大退化为 FCFS |
| **多级反馈队列 (MFQ)** | 抢占式 | 多级就绪队列，优先级从高到低，时间片从短到长 | 兼顾响应时间与短作业，408 公认最优 | 长作业可能饥饿 |

## 3. 同步互斥机制与信号量 (Semaphore)

::: info 💡 同步与互斥 4 大准则
1. **空闲让进**：临界区空闲时，应允许请求进入的进程立即进入；
2. **忙则等待**：已有进程处于临界区时，其他试图进入的进程必须等待；
3. **有限等待**：应保证请求进入临界区的进程在有限时间内能进入，避免死等；
4. **让权等待**：进程不能进入临界区时，应立即释放 CPU，避免忙等（`block()` 原语）。
:::

## 4. 死锁 4 大必要条件与银行家算法

- **死锁 4 大必要条件**：① **互斥**；② **不剥夺**；③ **请求和保持**；④ **循环等待**（破坏其中任意一个即可预防死锁）。
- **银行家算法 (Banker's Algorithm)**：
  - 设系统有 $m$ 类资源，$n$ 个进程：
  - $\text{Need}[i, j] = \text{Max}[i, j] - \text{Allocation}[i, j]$
  - 当进程 $P_i$ 请求 $\text{Request}_i$ 时，必须同时满足 $\text{Request}_i \le \text{Need}_i$ 且 $\text{Request}_i \le \text{Available}$ 才能尝试分配；
  - 尝试分配后执行安全性算法：寻找是否存在一个包含所有进程的**安全序列**，若存在则正式分配，否则拒绝本次请求。
