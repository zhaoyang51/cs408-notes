## 🏗️ I/O 软件五层层次结构

```
[用户层 I/O 软件]         ── SPOOLing 系统、格式化 I/O 库函数 (printf, scanf)、系统调用接口
       │
[设备独立性软件]          ── 设备命名与逻辑物理映射 (LUT)、设备保护、缓冲区管理、差错处理、设备分配
       │
[设备驱动程序]            ── 向上层提供统一抽象，向下与硬件寄存器直接通信，执行具体 I/O 指令
       │
[中断处理程序]            ── 当 I/O 硬件完成传输后，响应硬件中断，唤醒等待进程
       │
[物理硬件与控制器]        ── 机械部件、电气控制电路、状态/控制/数据寄存器
```

::: tip 💡 核心考点辨析
* **逻辑设备表 (LUT)** 位于哪一层？$\to$ **设备独立性软件层**！它将用户程序使用的逻辑设备名（如 `stdout`）映射到具体系统的物理设备名。
:::

## ⏳ 单双缓冲区平均处理耗时模型

> **基本参数设定**：
> * 设外设向操作系统内核缓冲区输入一块数据耗时为 **$T$**；
> * 操作系统将数据从内核缓冲区搬运至用户工作区耗时为 **$M$**；
> * CPU 对用户工作区中的数据进行计算处理耗时为 **$C$**。

```
[外设] ──(T)──> [内核缓冲区] ──(M)──> [用户工作区] ──(C)──> [计算完成]
```

### 1. 单缓冲区模型
* 由于只有一个内核缓冲区，**外设冲入缓冲区与系统从缓冲区传出数据必须串行互斥**！
* 处理一块数据的平均耗时为：
  $$\mathbf{\text{Time}_{\text{single}} = \max(C, T) + M}$$

### 2. 双缓冲区模型
* 系统配置两个缓冲区（Buffer 1 与 Buffer 2），当外设向 Buffer 1 灌入数据时，CPU 可以流水线式处理 Buffer 2 中的数据；
* 处理一块数据的平均耗时为：
  $$\mathbf{\text{Time}_{\text{double}} = \max(C + M, \ T)}$$
  * 若 $C + M < T$：CPU 计算与搬运速度快于外设输入，瓶颈在外设，平均耗时为 $T$；
  * 若 $C + M > T$：外设速度极快，瓶颈在 CPU 搬运与计算，平均耗时为 $C + M$。

## 📋 四级设备分配与 SPOOLing 假脱机技术

### ❓ 独占设备的四级安全分配流程

$$\text{逻辑设备名} \xrightarrow{\text{查 LUT / SDT}} \text{分配设备 (DCT)} \longrightarrow \text{分配控制器 (COCT)} \longrightarrow \text{分配通道 (CHCT)}$$

1. **SDT (系统设备表)**：记录全系统所有物理设备的状态及其 DCT 指针；
2. **DCT (设备控制表)**：每个物理设备一张，记录设备类型、状态、等待队列指针、相连的 COCT 指针；
3. **COCT (控制器控制表)**：记录控制器状态、相连的通道 CHCT 指针；
4. **CHCT (通道控制表)**：记录通道状态及等待该通道的控制器队列。

---

### ❓ SPOOLing 假脱机技术核心架构

```
┌─── 磁盘外存区 ────────────────┐      ┌─── 内存核心区 ────────────────┐
│  输入井: 暂存输入外设传来的数据  │ <──> │  输入缓冲区: 暂存输入数据     │ ──> 输入进程
│  输出井: 暂存用户进程待打印数据  │ <──> │  输出缓冲区: 暂存待打印输出数据 │ ──> 输出进程
└───────────────────────────────┘      └───────────────────────────────┘
```
1. **输入井与输出井**：在高速磁盘上开辟的大容量专用区域；
2. **输入缓冲区与输出缓冲区**：在内存中开辟的暂存对冲区；
3. **输入进程与输出进程**：在后台常驻运行的守护进程，**逻辑上模拟早期硬件“外围机”**；
4. **核心作用**：将一台物理上独占的低速设备（如打印机），改造为**供多个并发进程分时共享的虚拟逻辑设备**！

## 💽 六大磁盘调度算法与边界辨析

| 算法名称 | 扫描方向与移动特性 | 转向边界条件 | 优缺点与考研特征 |
| :--- | :--- | :--- | :--- |
| **FCFS (先来先服务)** | 按请求到来的先后顺序移动 | 无 | 公平简单，但平均寻道距离极长，性能极差 |
| **SSTF (最短寻道优先)** | 每次选择距离当前磁头最近的磁道 | 随邻近动态改变 | 每次寻道局部最优；**致命缺点是远离磁头的边缘磁道可能产生严重饥饿** |
| **SCAN (电梯算法)** | 沿固定方向移动，边走边服务请求 | **必须行进至磁盘的最外端或最内端尽头**才折返 | 消除了饥饿现象；但在刚调头的边缘区域响应不均 |
| **C-SCAN (循环扫描)** | **严格单向服务**（如仅从外向内） | **必须移动到尽头**后快速空载返回最起点 | 提供更加均匀的寻道等待时间 |
| **LOOK (电梯改进)** | 沿固定方向移动，边走边服务 | **只要前进方向上已无新的请求，立即提前调头**（无需走到底） | 减少了无意义的空载寻道移动 |
| **C-LOOK (循环改进)** | **严格单向服务** | **前方无请求时，直接返回最远端请求处**（不必返回 0 磁道） | 408 综合考核最高频算法 |

## ⚡ 固态硬盘 (SSD) 读写特性与磨损均衡

### ❓ SSD 页写块擦特性
* **读写基本单位**：以 **页 (Page)** 为最小单位进行读写（通常 4KB）；
* **擦除基本单位**：以 **块 (Block)** 为最小单位进行擦除（通常由多个页组成，如 128~256 页）；
::: tip 💡 核心考点：写前必须擦除
若某页已有数据，若要覆盖写入，必须先将整个闪存块擦除！
系统采用**异地更新**：将新数据写入空闲新页，并将原页标记为“无效页”，后续通过垃圾回收 (GC) 搬运有效页并整块擦除。
:::

---

### ❓ 动态磨损均衡 vs 静态磨损均衡

* **动态磨损均衡 (Dynamic Wear Leveling)**：
  * 当有新数据写入时，主控优先挑选**擦写次数少、寿命损耗小的空闲新块**写入。
* **静态磨损均衡 (Static Wear Leveling)**：
  * 在动态磨损均衡的基础上更进一步：主控会自动监控长期不改动的冷数据（如系统文件），主动将这些冷数据**从原本的老块搬运到高磨损块中驻留**，从而**腾出擦写次数少的新块用于承载高频擦写数据**，实现整盘物理寿命最大化！

## 🧮 经典真题大题：系统最大并发 I/O 速率计算

### ❓ 408 经典手写算例（1180 MB/s 推导）

> **真题设定**：
> * 某系统包含 **2 个磁盘控制器**，连接 **4 个磁盘驱动器**（每个控制器接 2 个磁盘）；
> * 包含 **2 个终端控制器**，连接 **20 个串行线的终端**（每个控制器接 10 个终端）；
> * **硬件约束规则**：
>   1. 当一个磁盘在处理命令时，磁盘控制器可以向另一个磁盘发命令，**但一次只允许一个磁盘在进行 I/O 数据传输**；
>   2. 终端控制器**可同时并发处理与其相连的所有设备同时传输的数据**；
>   3. 所有控制器均具备 DMA 控制能力；
>   4. 磁盘驱动器传输速率为 **$480\text{ MB/s}$**；
>   5. 终端设备传输速率为 **$11\text{ MB/s}$**。
> * ❓ **求该系统所能达到的最大 I/O 传输速率？**

#### 解题严密推导过程：
1. **分析磁盘子系统最大并发 I/O 吞吐率**：
   * 系统共有 2 个磁盘控制器；
   * 由于每个控制器“一次只允许一个磁盘在进行 I/O”，因此单个磁盘控制器同一时刻的极限速率为 $480\text{ MB/s}$；
   * 2 个独立磁盘控制器可完全并行工作：
     $$V_{\text{disk}} = 2 \times 480\text{ MB/s} = \mathbf{960\text{ MB/s}}$$
2. **分析终端子系统最大并发 I/O 吞吐率**：
   * 系统共有 20 个串行终端设备，分属 2 个终端控制器；
   * 题目指明“控制器可同时处理与其相连的设备同时传来的数据”，即所有 20 个终端均可实现完全并发；
   * 20 个终端设备的总并发传输速率为：
     $$V_{\text{terminal}} = 20 \times 11\text{ MB/s} = \mathbf{220\text{ MB/s}}$$
3. **计算系统最大并发 I/O 速率**：
   $$V_{\text{total}} = V_{\text{disk}} + V_{\text{terminal}} = 960\text{ MB/s} + 220\text{ MB/s} = \mathbf{1180\text{ MB/s}}$$
