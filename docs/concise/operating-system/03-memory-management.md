## 1. 4 大页面置换算法性能对比

| 置换算法 | 算法选择淘汰策略 | 命中率 / 性能表现 | Belady 异常 | 硬件支持需求 |
|:---|:---|:---:|:---:|:---|
| **最佳置换 (OPT)** | 淘汰以后**永不使用**或**在最长时间内不再被访问**的页面 | 理论最高（性能上限） | ❌ 无 | 无法实现（需预知未来） |
| **先进先出 (FIFO)** | 淘汰**最早进入内存**的页面 | 较差 | **✅ 存在 Belady 异常**（分配物理块增多，缺页次数反而增加） | 仅需简单队列 |
| **最近最久未使用 (LRU)** | 淘汰**最近一段时间内最久没有被访问过**的页面 | 极佳，最接近 OPT | ❌ 无 | 需寄存器/栈等硬件支持，开销大 |
| **时钟置换 (CLOCK)** | 循环遍历，访问位为 0 则置换，为 1 则置 0 给一次机会 | 接近 LRU，开销低 | ❌ 无 | 每页仅需 1 位访问位 |
| **改进型 CLOCK** | 优先淘汰 `(访问位=0, 修改位=0)`，次选 `(0, 1)`，再次 `(1, 0)`，最后 `(1, 1)` | 减少磁盘 I/O 写回开销 | ❌ 无 | 需访问位与修改位 |

## 2. 虚拟内存请求分页地址转换与缺页中断流程

1. **查 TLB 快表**：
   - 若命中 ➔ 得到物理页框号，直接合成物理地址；
2. **TLB 未命中，查主存页表**：
   - 检查状态位（有效位）：
     - 若有效位 $= 1$（在内存）➔ 得到页框号，写入 TLB，合成物理地址；
     - 若有效位 $= 0$（不在内存）➔ 产生**缺页中断 (Page Fault)**；
3. **缺页中断处理流程**：
   - 缺页中断属于**内部异常（故障 Fault）**，在指令执行期间产生；
   - 操作系统调用缺页处理程序，检查内存是否有空闲物理块；
   - 若无空闲块，依据置换算法（如 LRU）淘汰一个页面（若被修改过则先写回磁盘）；
   - 将所需页面从磁盘调入内存，修改页表项与 TLB；
   - **重新执行被中断的那条指令**。
