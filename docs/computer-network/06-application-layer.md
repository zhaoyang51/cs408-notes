# （一）网络应用模型

## 网络应用模型

- **客户/服务器模型（C/S）**：服务器处于被动等待，客户机主动请求。服务器性能常成为瓶颈。

- **P2P 模型（Peer-to-Peer 对等模式）**：节点既是客户也是服务器，可扩展性好。


---

# （二）域名系统（DNS）

## 域名系统（DNS）

- **概念与层次结构**：根域名服务器 -> 顶级域名服务器（TLD: .com, .cn） -> 权限域名服务器 -> 本地域名服务器。

- **解析过程**：递归查询（本地域名服务器代查）与迭代查询（本地域名服务器逐级请求）。基于 UDP/TCP 53 端口。


---

# （三）文件传输协议（FTP）

## 文件传输协议（FTP）

- 基于 TCP；**控制连接（端口 21）**：整个会话期间一直保持；**数据连接（端口 20）**：每次文件传输临时创建。

- 主动模式 PORT（服务器从 20 连客户端）与被动模式 PASV（客户端连服务器随机端口）。


---

# （四）电子邮件

## 电子邮件

### 1. 组成结构

- 用户代理（UA）、邮件服务器、邮件发送协议与读取协议。

### 2. SMTP 协议（简单邮件传输协议）

- 基于 TCP 25 端口，推动式（Push）协议，传输 7 位 ASCII 码（MIME 扩展多用途网际邮件扩充）。

### 3. POP3 与 IMAP 协议

- 拉取式（Pull）协议；POP3（基于 TCP 110 端口，下载后本地处理）；IMAP（基于 TCP 143 端口，保持与服务器同步）。


---

# （五）万维网（WWW）与 HTTP

## 万维网（WWW）与 HTTP

### 1. WWW 核心三要素

- URL（统一资源定位符）、HTTP（超文本传输协议）、HTML（超文本标记语言）。

### 2. HTTP 协议特点与报文格式

- 无状态协议（借助 Cookie/Session 记录状态）；请求报文（方法 GET/POST/HEAD/PUT/DELETE, URL, 协议版本）与响应报文（状态码 1xx, 2xx 成功 200, 3xx 重定向 301/302, 4xx 客户端错 400/403/404, 5xx 服务器错 500/502/503）。

### 3. HTTP 发展演进

- **HTTP/1.0**：非持续连接（每个对象建立一次 TCP 连接，耗费 2RTT）。

- **HTTP/1.1**：持续连接（非流水线方式与流水线方式，节省 RTT）。

- **HTTP/2.0**：多路复用（单个 TCP 多流并发）、二进制分帧、头部压缩 HPACK、服务器推送。

- **HTTP/3.0**：基于 UDP 的 QUIC 协议，解决 TCP 队头阻塞，实现 0-RTT 建连与连接迁移。
